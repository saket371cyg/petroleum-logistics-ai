# Agentic AI Decision Intelligence Platform — Petroleum Dealer Logistics

A dealer-facing, full-stack decision-support platform: demand forecasting,
inventory risk monitoring, order recommendation, refinery slot coordination,
fleet/driver management, compliance and maintenance monitoring, and dispatch
scheduling via Hill Climbing optimization.

**All operational data (sales, inventory, fleet, drivers, refineries,
compliance) is SYNTHETIC**, generated by `backend/data/synthetic/generate_data.py`.
This is not real Reliance/IOCL/BPCL/HPCL data.

---

## What's real vs synthetic

| | |
|---|---|
| **Real** | Application logic, all 10 agents, ML forecasting model (trained, not mocked), Hill Climbing optimizer, BFS/DFS utilities, A*/Dijkstra route search, database schema, REST API, React dashboard |
| **Synthetic** | Fuel sales history, inventory levels, fleet/driver records, refinery slots, traffic/weather conditions |

## Quick start (local, no Docker)

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # defaults to SQLite, zero setup

python data/synthetic/generate_data.py   # generates synthetic CSVs
python seed_db.py                         # creates tables + loads data
python -m app.ml.train_demand_model       # trains the demand forecast models

uvicorn app.main:app --reload --port 8000
```

Backend is now running at http://localhost:8000 (interactive API docs at
http://localhost:8000/docs).

**Demo login:** `dealer1@example.com` / `password123`

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs at http://localhost:5173 and proxies `/api/*` to the backend
at `localhost:8000` (see `vite.config.js`).

Open http://localhost:5173, log in with the demo credentials above, and
you'll land on the dealer dashboard.

## Quick start (Docker)

```bash
docker-compose up --build
```

This starts Postgres, the backend (which generates synthetic data, seeds
the DB, and trains the ML model automatically on container startup), and
the frontend (served via nginx, proxying `/api` to the backend).

- Frontend: http://localhost:5173
- Backend: http://localhost:8000

## Demo scenario (matches the project spec)

1. Log in as `dealer1@example.com`.
2. **Dashboard** shows diesel at CRITICAL / low days-of-stock (seeded deliberately).
3. **Forecast** page shows a 7–14 day XGBoost-style RandomForest prediction with real backtest MAE/RMSE/MAPE.
4. **Orders** page → "Get recommendation" for DIESEL → AI recommends an order quantity with a full explanation → create and approve the order.
5. **Dispatch** page → select the approved order → "Optimize" → Hill Climbing runs (5 random restarts) and returns a tanker, driver, loading slot, ETA, cost, and risk level, with an explanation that names the local-optimum caveat.
6. Approve the dispatch, then mark it delivered — inventory automatically replenishes and analytics update.
7. **Compliance** and **Maintenance** pages show rule-based alerts (expired licenses/permits, high-risk tankers).
8. **AI assistant** answers operational questions by querying the live database (no external LLM dependency required to run this project — see note below).

## Design notes / deviations from a literal reading of the spec

- **Database default is SQLite**, not Postgres, for the local quick-start
  path (zero setup, no separate DB server to install). Switching to Postgres
  is a one-line change to `DATABASE_URL` in `.env`, and `docker-compose.yml`
  runs the real Postgres path. The SQLAlchemy models are written to be
  portable between both.
- **Orchestration is a plain Python pipeline function**
  (`app/orchestration/dispatch_orchestrator.py`), not a LangGraph
  `StateGraph`. Each agent is still an independent, swappable unit with a
  typed interface — wrapping them as LangGraph nodes later is a drop-in
  change that doesn't require touching agent internals. This was a
  deliberate simplification to keep the single linear workflow transparent
  to read and grade.
- **The AI Assistant does not call an external LLM.** It's a rule-based
  intent router + live database queries — genuinely functional without any
  API keys or paid services. `app/ai_assistant/assistant.py` documents
  exactly where a real LLM call (e.g., Anthropic's Messages API) would slot
  in as a drop-in replacement for the answer-composition step.
- **Hill Climbing does not guarantee a global optimum** — this is
  intentional and documented in `app/optimization/hill_climbing.py` and in
  every dispatch explanation returned by the API. Random-restart hill
  climbing is used to mitigate (not eliminate) the local-optimum/plateau/ridge
  problem.
- **Compliance and maintenance logic is fully rule-based** (no ML/LLM), per
  the spec's explicit requirement for deterministic compliance checks.

## Running tests

```bash
cd backend
source venv/bin/activate
pip install pytest
pytest tests/ -v
```

(Add test files under `backend/tests/` — the app's modular agent design
means each agent can be unit-tested independently by constructing a test
DB session and asserting on agent outputs.)
